# Security review — 2026-11-01

Scope: omniNote 0.0.6, a local-first Electron app. Reviewed the [vibe-check](https://github.com/benavlabs/vibe-check) and [VibeAudits](https://vibeaudits.com/blog/vibe-coded-app-security-checklist) checklists against the actual application boundaries: imported files, extension packages, the renderer, IPC, local storage, and releases.

## Fixed on `codex/security-audit`

- File picker imports now stop at 100 MB while reading. Previously they read the entire selected file before the store rejected an oversized import, which could freeze or exhaust the Electron main process.
- **Open original** now refuses executable and shortcut attachments. Users can still inspect those files from the workspace folder; omniNote no longer launches them through the asset action.
- Asset reads now resolve and constrain stored paths to the workspace's asset directory, including symlink targets. A corrupted asset record can no longer point the reader at an arbitrary local file.
- `.env` and `.env.*` are ignored by Git, while `.env.example` remains eligible for tracking. No environment files are currently tracked.

## Existing controls checked

- Renderer uses `sandbox: true`, `contextIsolation: true`, and `nodeIntegration: false`. IPC handlers verify the sender is the main frame. App navigation and new windows are blocked.
- Main UI has a restrictive CSP. Document previews run in sandboxed iframes with a separate CSP and sanitized markup. External links are limited to HTTP, HTTPS, and mailto.
- SQLite queries use bound parameters. Imported asset size is capped in storage. Marketplace packages are fetched over HTTPS, checked against a catalog SHA-256 digest, size limited, restricted to flat allowed filenames, and placed in extension sandboxes.
- No login, cloud database, public app API, payment flow, cookies, or AI endpoint exists in this phase. The related checklist items and the web endpoint scanner do not apply to this desktop build.

## Dependency audit

`npm audit` reported 21 moderate advisories, 0 high, and 0 critical. With `--omit=dev`, 9 moderate advisories remain, all under `exceljs` and its `archiver`/`uuid` dependency tree. omniNote uses `exceljs` to **read** XLSX previews; the reported `archiver` path concerns archive writing and the `uuid` advisory requires a caller-supplied buffer, neither of which is used by this preview path. The remaining advisories are in `electron-builder` packaging dependencies. npm's suggested automatic fix would downgrade major direct dependencies, so the lockfile was left unchanged. Recheck these advisories before the next release and upgrade when compatible fixes are available.

Marketplace archive SHA-256 checks detect a changed package relative to the downloaded catalog, but the catalog is not independently signed. A compromise of its hosting origin could replace both the catalog digest and package. Signing marketplace metadata is a future trust improvement; installed extensions remain disabled until the user enables them and grants declared capabilities.

This review does not include a penetration test or inspection of every past Git commit. Local notebook privacy still depends on the operating system account and filesystem permissions; omniNote does not encrypt notebooks at rest.
