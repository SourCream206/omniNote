# Tauri security and size review — 2026-11-14

Scope: current local-first Tauri app, workspace core, extension marketplace, updater, and production renderer. The old `codex/security-audit` branch is fully contained in `main`; its Electron-specific code is retired.

## Changes in this review

- Restore the old audit's launch guard in Tauri: **Open original** rejects executable and shortcut attachments while keeping them available in the workspace.
- Bind updater signatures to the announced version. Arch updates use a separately signed package and `pacman` after the user's confirmation and PolicyKit authentication.
- The release workflow verifies the Arch signature and updater manifest entry before publishing.

## Checks

- Root `npm audit`: 0 critical, 0 high, 2 moderate. Both findings trace to `exceljs` using `uuid` 8.x. Its two call sites invoke `uuidv4()` without the caller-supplied buffer required by [GHSA-w5hq-g745-h8pq](https://github.com/advisories/GHSA-w5hq-g745-h8pq). The offered fix downgrades `exceljs` from 4.x to 3.4.0, so it is deferred; revisit on the next dependency update.
- Tauri npm lockfile: 0 findings. No tracked `.env` or private key files. TypeScript tests, typecheck, and renderer build pass.
- Rust tests and a real installed Arch update need CI and device verification; the local machine has no Rust toolchain or Linux environment.

## Size and speed

Production build: initial UI JavaScript 735 kB (230 kB gzip), document preview 886 kB (267 kB gzip), XLSX parser 929 kB (256 kB gzip), PDF worker 1.27 MB. Document preview and XLSX are already loaded on demand; moving them into the startup bundle would regress load time. The remaining candidates are page-data loading at startup and full-file asset reads for large documents. Change those after a representative workspace profile, since they affect storage and viewer behavior.
